# Architecture and release boundaries

One site (`home`) per instance, arbitrary panel banks, one logical battery at the aggregate AC boundary. One container serves FastAPI, the web GUI and a durable queue; a single bounded subprocess executes jobs sequentially. Use one Uvicorn worker. CPU libraries use two threads; a job has a five-minute wall-clock limit. Cancellations retain a training checkpoint, and interrupted jobs return to the queue on restart.

SQLite/WAL stores versioned site configuration, immutable raw observation revisions, idempotent batch acknowledgements, quality reviews, original weather responses, forecast snapshots, jobs and model metadata. Analytical canonical history can be exported to Parquet. The schema version is recorded; the initial release has schema version 1. Forecast and weather journals are append-only. Model activation and old-lease invalidation happen in one transaction. Retain previous model bundles for rollback.

Energy/power planning uses kWh/kW at the AC bus. Battery state is stored kWh; charging adds `eta_charge * AC energy`, discharge removes `AC energy / eta_discharge`. DC observations are converted explicitly before composition. Neither charging nor inverter loss is household consumption. PV banks share configured inverter clipping, and battery export shares its discharge/inverter power limit with household demand.

UTC start/end intervals are exclusive at end. Tariff/calendar features use an IANA zone. A tariff segment also splits at UTC offset changes, including the repeated hour in autumn. Open-Meteo radiation labels are preceding-hour averages; temperature is a sample at the end label. Solar geometry is evaluated at the interval midpoint through pvlib. Forecast run initialization is distinct from provider availability and service receipt.

The service owns configuration. Optimistic revisions reject concurrent stale edits. The HA bridge owns selected entity/statistic discovery, source metadata, bounded Recorder reads and durable retry/checkpoint forwarding. Output entities cannot become inputs, including renamed integration entities. Large forecast arrays stay outside HA Recorder. The coordinator publishes one snapshot; local timers expire cached readiness even when polling fails.

Forecasts cover a rolling 48 hours, including fractional first/last bins. Models operate hourly; tariff/battery simulation splits at quarter-hour and exact tariff boundaries. This does not recover measured intra-hour peaks. Phase-constrained installations remain unvalidated under the aggregate simulator.

Physical PV and weekday/hour load profiles are useful baselines. CPU LightGBM PV candidates require issue-time weather; the causal TCN uses 168 past hours and a direct 49-bin quantile head (49 bins cover the fractional edges of a 48-hour horizon). The initial CNN uses known calendar cycles. Its small recent residual-profile branch retains the long-term branch, has a 7–30-day window, bounded influence and a separate chronological validation gate. It does not learn from incomplete future outcomes.

Jobs run hourly bias/uncertainty review, daily recent-profile adaptation and weekly main training when quality/sample gates permit. Train/calibration/test targets are disjoint with a 49-hour embargo; missing targets omit windows. Training-only scaling, ordered nonnegative quantiles, immutable artifacts, held-out baseline comparisons and atomic activation constrain promotion. Failed candidates keep the active model. Weather/optional-feature ablations need commissioned data before activation.

Paired completed residual trajectories preserve hour and PV/load dependence. Scenario optimization uses common causal household-first policy templates and independent bootstrap draws for verification; simulated binomial bounds quantify Monte Carlo noise only. They do not prove real-world independent path confidence. Current API responses deliberately authorize zero export until separate operating-envelope/tail validation has been commissioned.

Authentication is an installation-local administrator with scrypt hashes, expiring HttpOnly/SameSite cookies, CSRF tokens, origin checks and scoped hashed bearer tokens. Private data stays in `/data` with restricted permissions. Only coordinates/model/field requests go to Open-Meteo. No HA/Proxmox credentials are needed by the service. No device actuation endpoints or control-service calls exist.
