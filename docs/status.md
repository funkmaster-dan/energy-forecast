## Validation recorded

Basic service pytest/Ruff and integration protocol/retry pytest/Ruff; TypeScript/Vite and frontend lint; manual Playwright desktop/mobile configuration and live dashboard checks; Docker health/authentication/persistence and isolated HA lifecycle checks. Real household history was used for chronological train/calibration/test comparisons, with no test targets fitted into candidate parameters. Failed load candidates were retained for review rather than activated. Private commissioning records contain the actual sensor identities, model metrics and installed-site assumptions; they are excluded from public Git.

Source roles are configurable. Retired monitoring inputs are historical only; current PV-bank inputs and post-inverter/household/battery measurements come from the installation's selected live integrations. Sensor choices, AC/DC boundaries, validity dates, priorities, epochs, battery assumptions, tariff/calendar sources and operational freshness settings use GUI controls, not JSON editing.

Neither component controls a battery. Successful predictive validation is separate from operating-path confidence. In this alpha, live discretionary export remaining/now/power stay zero until supported acceptance is implemented and commissioned. Append-only records continue collecting the evidence needed for that decision.

Optional extensions beyond the initial personal deployment include full per-phase/MILP optimization, tariff-specific tiered billing and nationwide automatic school-date scrapers. The initial specification permits aggregate advisory planning and explicit reviewed calendar imports; mandatory unverified phase constraints block readiness.
